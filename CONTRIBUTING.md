# 🤝 Contributing to Full Stack Web Development Notes

Thank you for your interest in improving or contributing to these class notes and tasks! Whether you are fixing a typo, adding notes from a lecture, or suggesting an alternative solution to an assignment, your contributions are welcome.

---

## 📌 Guidelines

### 1. Folder Structure & Naming
- If adding code for a new lecture or assignment, create a folder named after the date or topic (e.g., `25-Sep` or `01-Oct-JavaScript-Basics`).
- Keep code organized with separate files for markup (`.html`), styling (`.css`), and scripting (`.js`).

### 2. Code Quality & Standards
- Use semantic HTML tags where possible (`<header>`, `<main>`, `<section>`, `<article>`, `<footer>`).
- Keep CSS modular and well-commented.
- Use 2-space indentation (configured in `.editorconfig`).
- Test all pages across responsive screen widths before committing.

### 3. Git Workflow
1. **Fork or create a new branch**:
   ```bash
   git checkout -b feature/topic-name
   ```
2. **Make your changes** and test them in your browser.
3. **Commit with a descriptive message**:
   ```bash
   git commit -m "task(date): add solution for DOM manipulation exercise"
   ```
4. **Push to your branch and open a Pull Request**.
